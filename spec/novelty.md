## 3. Что ново у нас

1. **Семантика ограничений.** Т1 на шаге 4 — механизированное доказательство корректности структурных правил таблицы 4 и правил ключей (§4.5, 4p1–4p4) относительно денотации `check`, то есть утверждения §4.1. У него этого уровня нет ни в модели («nothing below the tool level»), ни в виде доказательства: верификатор проверен только на векторах.
2. **AAT-02.** Его модель — для -01; наша — для -02.
3. **Любая длина.** Т1 и последующие теоремы — для цепочки любой длины; у него — не более 4 токенов. Оговорка: по §4.3 длина и так ограничена `MAX_DELEGATION_DEPTH + 1` (не меньше 9), поэтому сильный аргумент здесь — «больше 4», а не «бесконечность».
4. **Время целиком (I3).** У него только порядок `exp`.
5. **Исполняемая модель с доказательствами.** Lean-модель — второй независимый оракул для векторов (после его TS-верификатора), но со связью «код ↔ теорема». Три независимых вердикта на 229 векторах: автор, Давлятшин, мы.
6. **Т7 — механизированное подтверждение B9/B10**, не новое наблюдение. Ценность: объясняет доказательством, почему набор векторов не может покрыть эти шаги как единственную ошибку.

## 5. Формулировка вклада (черновик, на утверждение Ерасылу)

> Исполняемая модель верификатора AAT-02 на Lean с машинно-проверенными
> доказательствами: (1) структурные правила сужения прав из спецификации
> корректны относительно их смысла — для цепочек любой длины и с ограничениями
> аргументов, которых нет в существующей формальной модели (ProVerif,
> Давлятшин, AAT-01, до 4 токенов, без семантики ограничений); (2) проверки,
> которые спецификация и независимый отчёт считают избыточными, действительно
> следуют из остальных. Модель сверена с 229 авторскими тестовыми векторами.
> Работа дополняет отчёт Давлятшина, а не конкурирует с ним.

Утверждения (1)–(2) и «сверена с векторами» станут верны только после шагов 4–6;
до тех пор — как план с достигнутыми вехами.
